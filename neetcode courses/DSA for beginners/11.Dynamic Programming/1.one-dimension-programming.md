# One Dimensional Dynamic Programming

Dynamic programming (DP) is often considered one of the hardest topics in computer science, but the idea is simpler than people make it seem. In this chapter, we break it down into smaller, easier-to-understand concepts and show how to solve problems with it.

Some DP problems are difficult, but the general concept is not.

## What is dynamic programming?

Simply put, it is an optimized version of recursion.

It takes a large problem and breaks it into smaller subproblems. We say it is optimized recursion because it is often more efficient in both time and space.

Let us revisit the Fibonacci sequence, which we discussed earlier in the course. We compute the $n$th Fibonacci number using:

$$
F(n) = F(n - 1) + F(n - 2)
$$

### Brute force

```js
function bruteForce(n) {
  if (n <= 1) {
    return n;
  }

  return bruteForce(n - 1) + bruteForce(n - 2);
}
```

The time complexity of this brute-force solution is $O(2^n)$ because each call branches into two more calls.

With dynamic programming, we can reduce the time complexity to $O(n)$.

---

## Dynamic programming vs. recursion

If we look at the recursion tree for `bruteForce(5)`, we calculate `F(2)` multiple times. That is extra work, and it adds up quickly as the input grows.

DP helps us avoid this repeated computation by using memoization, which is just a fancy name for caching.

The idea is simple:

- compute a value once
- store it in a cache
- reuse it later when that same subproblem appears again

For example, if we calculate `F(3)`, we can store the result in a hash map or array. If we need `F(3)` again later, we can return it from the cache in $O(1)$ time.

```js
function memoization(n, cache) {
  if (n <= 1) {
    return n;
  }

  if (cache[n] != 0) {
    return cache[n];
  }

  cache[n] = memoization(n - 1, cache) + memoization(n - 2, cache);
  return cache[n];
}
```

### Key changes in the memoized version

- We added a `cache` parameter.
- We check whether the value already exists in the cache before recursing.
- After computing a value, we store it so we can reuse it later.

---

## Top-down approach (memoization)

This is the top-down approach because we start from the root of the recursion tree and work downward toward the base cases.

There is also a bottom-up approach that starts from the base cases and works upward.

The time complexity of the memoized solution is $O(n)$ because each Fibonacci value is computed once and then reused. The space complexity is also $O(n)$ because we store values in the cache.

---

## Bottom-up approach (tabulation)

We can compute the value of `n` using `n - 1` and `n - 2`.

Suppose we have an array of size 5 that helps us compute the 5th Fibonacci number. The array would look like this:

```js
[0, 1, 1, 2, 3, 5];
```

The value stored at index `i` represents `F(i)`.

The time complexity is $O(n)$ and the space complexity is $O(n)$.

But we can do even better.

### Space optimization

We only ever need the previous two Fibonacci values to compute the next one. So instead of storing the whole array, we can keep just two values in memory.

This reduces the space complexity to $O(1)$.

```js
function dp(n) {
  if (n < 2) {
    return n;
  }

  let dp = [0, 1];
  let i = 2;

  while (i <= n) {
    let tmp = dp[1];
    dp[1] = dp[0] + dp[1];
    dp[0] = tmp;
    i++;
  }

  return dp[1];
}
```

This is an example of 1D dynamic programming because the result of each subproblem can be stored in a 1D data structure proportional to `n`.

# Climbing Stairs

**Difficulty:** Easy

**Topics:** DP, recursion, memoization

**Company Tags:** None

You are given an integer `n` representing the number of steps to reach the top of a staircase. You can climb with either `1` or `2` steps at a time.

Return the number of distinct ways to climb to the top of the staircase.

## Example 1

Input:

```js
n = 2;
```

Output:

```js
2;
```

Explanation:

```js
1 + 1 = 2
2 = 2
```

## Example 2

Input:

```js
n = 3;
```

Output:

```js
3;
```

## 1. Dynamic Programming (Top-Down)

### Intuition

This is the optimized version of the recursive solution.

The key observation is that the same subproblems repeat many times while exploring choices of `1` step or `2` steps.

For example, the number of ways from step `i` is always the same whenever we reach `i`.

Instead of recomputing, we store the result the first time we compute it and reuse it later. This is exactly what memoization does.

### Algorithm

1. Create a cache array of size `n`, initialized to `-1`.
2. Define a recursive function `dfs(i)`.
3. If `i === n`, return `1`.
4. If `i > n`, return `0`.
5. If `cache[i]` is already filled, return it.
6. Otherwise, compute:
   - `dfs(i + 1) + dfs(i + 2)`
7. Store the result in `cache[i]` and return it.

```js
class Solution {
  /**
   * @param {number} n
   * @return {number}
   */
  climbStairs(n) {
    const cache = new Array(n).fill(0);

    const dfs = (i) => {
      if (i >= n) return i === n;

      if (cache[i] !== 0) {
        return cache[i];
      }

      return (cache[i] = dfs(i + 1) + dfs(i + 2));
    };

    return dfs(0);
  }
}
```

### Time and space complexity

- Time complexity: $O(n)$
- Space complexity: $O(n)$

# House Robber

**Difficulty:** Medium

**Topics:** DP, recursion, memoization

**Company Tags:** None

You are given an integer array `nums` where `nums[i]` represents the amount of money in the `i`th house. The houses are arranged in a straight line, so the `i`th house is adjacent to the `(i - 1)`th and `(i + 1)`th houses.

You are planning to rob money from the houses, but you cannot rob two adjacent houses because the security system will automatically alert the police.

Return the maximum amount of money you can rob without alerting the police.

## Example 1

Input:

```js
nums = [1, 1, 3, 3];
```

Output:

```js
4;
```

Explanation:

```js
nums[0] + nums[2] = 1 + 3 = 4
```

## Example 2

Input:

```js
nums = [2, 9, 8, 3, 6];
```

Output:

```js
16;
```

## 1. Dynamic Programming (Top-Down)

### Intuition

The recursive solution recomputes the same subproblems many times. To optimize it, we store the result for each index once it is computed.

At every house `i`, you still have two choices:

- skip the house → move to `i + 1`
- rob the house → take `nums[i]` and move to `i + 2`

Using memoization, each index is solved only once.

### Algorithm

1. Create a `memo` array where `memo[i]` stores the maximum money from house `i`.
2. Define a recursive function `dfs(i)`.
3. If `i` is out of bounds, return `0`.
4. If `memo[i]` is already computed, return it.
5. Compute:
   - `skip = dfs(i + 1)`
   - `rob = nums[i] + dfs(i + 2)`
6. Store and return `max(skip, rob)` in `memo[i]`.
7. Start recursion from index `0`.

```js
class Solution {
  /**
   * @param {number[]} nums
   * @return {number}
   */
  rob(nums) {
    const memo = new Int32Array(nums.length).fill(-1);

    const dfs = (i) => {
      if (i >= nums.length) {
        return 0;
      }

      if (memo[i] !== -1) {
        return memo[i];
      }

      return (memo[i] = Math.max(dfs(i + 1), nums[i] + dfs(i + 2)));
    };

    return dfs(0);
  }
}
```

### Time and space complexity

- Time complexity: $O(n)$
- Space complexity: $O(n)$

## 2. Dynamic Programming (Space Optimized)

### Intuition

We do not actually need a full DP array.

At any house, we only care about:

- the best result up to the previous house
- the best result up to the house before that

So instead of storing everything, we keep two variables and update them as we move forward.

For each house:

- either skip it → keep the previous best
- or rob it → current money + best from two steps back

Pick the maximum.

### Algorithm

1. Initialize:
   - `rob1` = best up to house `i - 2`
   - `rob2` = best up to house `i - 1`
2. For each house value:
   - `newRob = Math.max(rob2, rob1 + currentHouseValue)`
   - update `rob1 = rob2`
   - update `rob2 = newRob`
3. After processing all houses, return `rob2`.

```js
class Solution {
  /**
   * @param {number[]} nums
   * @return {number}
   */
  rob(nums) {
    let rob1 = 0;
    let rob2 = 0;

    for (const num of nums) {
      const newRob = Math.max(num + rob1, rob2);
      rob1 = rob2;
      rob2 = newRob;
    }

    return rob2;
  }
}
```

### Time and space complexity

- Time complexity: $O(n)$
- Space complexity: $O(1)$
