# Async/Await

## Overview
The **async function** declaration creates a binding of a new async function to a given name. The **await keyword** is permitted within the function body, enabling asynchronous, promise-based behavior to be written in a cleaner style and avoiding the need to explicitly configure promise chains.

## Basic Async Function
```typescript
function resolveAfter2Seconds(): Promise<string> {
    return new Promise(resolve => {
        setTimeout(() => {
            resolve("resolved");
        }, 2000);
    });
}

async function asyncCall(): Promise<void> {
    console.log("calling");
    const result = await resolveAfter2Seconds();
    console.log(result);
}
```

## Sequential Asynchronous Execution
Performing tasks one after another, with each task starting only after the previous one has completed:

```typescript
async function fetchSequentially() {
  try {
    const response1 = await fetch("https://randomuser.me/api/?results=10");
    const data1 = await response1.json();
    console.log("response fetch1", data1);

    const response2 = await fetch("https://randomuser.me/api/?results=9");
    const data2 = await response2.json();
    console.log("response fetch2", data2);
  } catch (error) {
    console.error("error fetch", error);
  }
}

fetchSequentially();
```

## Parallel Asynchronous Execution
Starting several tasks at once and letting them all progress simultaneously using `Promise.all`:

```typescript
async function fetchInParallel() {
  try {
    const fetch1 = fetch("https://randomuser.me/api/?results=10");
    const fetch2 = fetch("https://randomuser.me/api/?results=9");

    const [response1, response2] = await Promise.all([fetch1, fetch2]);

    const data1 = await response1.json();
    const data2 = await response2.json();

    console.log("response fetch1", data1);
    console.log("response fetch2", data2);
  } catch (error) {
    console.error("error fetch", error);
  }
}

fetchInParallel();
```

## Key Benefits
- Cleaner, more readable code compared to promise chains
- Sequential and parallel execution patterns
- Better error handling with try/catch blocks
