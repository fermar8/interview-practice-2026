# API Design Basics

## REST Conventions

These conventions provide a practical baseline:

1. Use nouns for resources (`/users`, `/orders`), not verbs.
2. Use HTTP methods for actions:
   - `GET` read
   - `POST` create
   - `PUT` update
   - `DELETE` remove
3. Use plural names for collections.
4. Use query params for filtering/sorting (`/users?age=30`, `/users?sort=name`).
5. Keep naming conventions consistent across endpoints and parameters.
6. Version APIs to avoid breaking existing clients (`/v1/...` or versioned media types).

## Validation and Error Handling

Best practices:

1. Use correct HTTP status codes (`200`, `201`, `400`, `500`, etc.).
2. Return meaningful error messages with actionable detail.
3. Validate input data against expected constraints.
4. Keep a consistent error response shape (for example JSON with an `error` field).
5. Log server-side errors for debugging and trend analysis.

## Middleware and Authentication

Recommended patterns:

1. Use middleware for cross-cutting concerns (logging, auth, error handling).
2. Implement both authentication (identity) and authorization (permissions).
3. Prefer secure auth strategies (OAuth, JWT, API keys).
4. Configure CORS safely for browser clients.
5. Apply rate limiting to protect reliability and prevent abuse.
