# Interface vs Type

## Overview
There are two main tools to declare the shape of an object: **interfaces** and **type aliases**. They are very similar, and for the most common cases act the same.

## Basic Comparison

### Type Alias
```typescript
type BirdType = {
  wings: 2;
};
```

### Interface
```typescript
interface BirdInterface {
  wings: 2;
}
```

### Using Both
```typescript
const bird1: BirdType = { wings: 2 };
const bird2: BirdInterface = { wings: 2 };
```

## Structural Type System
Because TypeScript is a **structural type system**, it's possible to intermix their use:

```typescript
const bird3: BirdInterface = bird1;
```

## Extension and Inheritance

### Type Aliases with Intersection
```typescript
type Owl = { nocturnal: true } & BirdType;
type Robin = { nocturnal: false } & BirdInterface;
```

### Interfaces with Extension
```typescript
interface Peacock extends BirdType {
  colourful: true;
  flies: false;
}

interface Chicken extends BirdInterface {
  colourful: false;
  flies: false;
}

let owl: Owl = { wings: 2, nocturnal: true };
let chicken: Chicken = { wings: 2, colourful: false, flies: false };
```

## Error Messages
It is recommended to use **interfaces** over type aliases, specifically because you will get better error messages. TypeScript can provide terser and more focused messages when working with interfaces.

## Key Difference: Open vs Closed

### Interfaces are Open (Declaration Merging)
You can extend an interface by declaring it a second time:

```typescript
interface Kitten {
  purrs: boolean;
}

interface Kitten {
  colour: string;
}
```

### Type Aliases are Closed
A type cannot be changed outside of its declaration:

```typescript
type Puppy = {
  color: string;
};

type Puppy = {
  toys: number;
}; // This will throw an error
```

## Best Practices
- For **publicly exposed types**, it's a better call to make them an **interface**
- This allows for flexibility and extension in the future
- Type aliases are more flexible for complex types (unions, intersections, tuples)
