# Binary Trees: Sets and Maps

Sets and maps are interfaces that can be implemented with trees.

When implemented using balanced trees, common operations are efficient:

- insert: **O(log n)**
- delete: **O(log n)**
- search: **O(log n)**

This is similar to how stacks and queues are interfaces that can have different implementations.

## Sets

A set stores unique values.

Example phone-book names:

- Alice
- Brad
- Collin

With a tree-based set (often called a TreeSet), values remain sorted while preserving uniqueness.

## Maps

A map stores key-value pairs.

If implemented with a tree, it is commonly called a TreeMap.

Using the same phone-book theme:

- key: name (or last name)
- value: phone number (or any data type)

Tree-based maps stay ordered by key, and key operations run in **O(log n)**.

```text
{
	"Alice": 123,
	"Brad": 345,
	"Collin": 678
}
```

## Why Ordered Keys Matter

Tree implementations are useful when you need:

1. sorted traversal by key
2. efficient range queries
3. predecessor/successor lookups

Hash-based structures are often faster on average for exact lookup, but they do not keep keys sorted.

## Language Examples

Java and C++ have built-in ordered map/set structures. Python and JavaScript usually use libraries for sorted tree maps.

### Python

```python
from sortedcontainers import SortedDict

treemap = SortedDict({"c": 3, "a": 1, "b": 2})
```

### Java

```java
TreeMap<String, Integer> treeMap = new TreeMap<>();
```

### JavaScript

```javascript
const TreeMap = require("treemap-js");

const map = new TreeMap();
```

### C++

```cpp
#include <map>

std::map<std::string, int> treeMap;
```

## Closing Notes

Trees are one implementation option for sets/maps.

Later lessons will cover hash-based versions, which trade ordering for average-case constant-time operations.
