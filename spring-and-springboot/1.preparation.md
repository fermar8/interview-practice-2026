# 🎯 PART 1: 11 Technical Concepts You Can Discuss

## 1. Dependency Injection & Spring Annotations

**What it is in simple terms**: Spring automatically creates objects and passes them where needed

**Code Example**:
```java
@Service  // Tells Spring "this is a service"
public class PaqatoTrackingUpdateService {
    private final TrackingStateService trackingStateService;
    private final CarrierDataProviderConfigurationRepository repo;

    // Constructor injection - Spring provides these automatically
    public PaqatoTrackingUpdateService(
            TrackingStateService trackingStateService,
            CarrierDataProviderConfigurationRepository repo) {
        this.trackingStateService = trackingStateService;
        this.repo = repo;
    }
}
```

**What you can say**: "Spring Boot uses dependency injection via annotations like `@Service`, `@Component`, and `@Repository`. This loosely couples the code—you inject dependencies through constructors rather than creating objects manually. It's similar to how you'd pass dependencies in TypeScript with frameworks like NestJS."

**Confidence Level**: ⭐⭐⭐⭐ Can discuss comfortably

## 2. Message Queue Listeners (Event-Driven Architecture)

**What it is**: Code that automatically runs when a message arrives in a queue

**Code Example**:
```java
@Component
@Slf4j
public class SqsShipmentEventReceiver {
    
    @SqsListener(value = "${shipmentEvents.queue.url}", 
                 acknowledgementMode = SqsListenerAcknowledgementMode.ON_SUCCESS)
    public void receive(@Headers Map<String, Object> headers, 
                        SnsMessage snsMessage) {
        // This method runs automatically when a message arrives in SQS
        // Spring parses JSON, validates it, and calls this method
    }
}
```

**What you can say**: "We use `@SqsListener` annotation to automatically consume messages from AWS SQS queues. When an event arrives, Spring deserializes the JSON, validates it against a schema, and routes it to the handler. It's similar to event listeners in Node.js or callback handlers—you define once and Spring wires it up."

**Confidence Level**: ⭐⭐⭐⭐ Can discuss comfortably

## 3. Generic Types & Polymorphism

**What it is**: Writing flexible code that works with different data types

**Code Example**:
```java
// Generic base class with two type parameters
public class BiRegexStateResolver<T, E> {
    protected abstract Map<String, BiFunction<T, E, String>> defineExtractors();
}

// For Paqato, we specify: T = PaqatoShipmentData, E = PaqatoEvent
public class PaqatoStateResolver 
    extends BiRegexStateResolver<PaqatoShipmentData, PaqatoEvent> {
    
    @Override
    protected Map<String, BiFunction<PaqatoShipmentData, PaqatoEvent, String>> 
                        defineExtractors() {
        return Map.of(
            "shipmentType", this::shipmentType,
            "shipmentState", this::shipmentState,
            "eventId", this::eventId
        );
    }
}

// For DHL, we'd do the same but with different types
// public class DhlStateResolver extends BiRegexStateResolver<DhlData, DhlEvent>
```

**What you can say**: "We use Java generics and polymorphism to handle different carriers. The base `BiRegexStateResolver` class defines the structure, and each carrier (Paqato, DHL, etc.) extends it with their specific data types. It's like TypeScript generics—`<T, E>`—allowing one algorithm to work with multiple data structures."

**Confidence Level**: ⭐⭐⭐⭐ Can discuss comfortably

## 4. Spring Data & MongoDB Repository Pattern

**What it is**: Spring provides automatic database query methods

**Code Example**:
```java
@Repository
public class CarrierEventRepository {
    private final MongoTemplate template;

    public void insert(CarrierEvent carrierEvent) {
        this.template.insert(carrierEvent);
    }

    public Optional<CarrierEvent> findById(TrackingId trackingId) {
        return Optional.ofNullable(this.template.findById(trackingId, CarrierEvent.class));
    }

    public void setPolling(TrackingId trackingId, Polling polling) {
        final BasicQuery bq = new BasicQuery(new Document("_id", trackingId));
        final BasicUpdate bu = new BasicUpdate(
            new Document("$set", new Document("polling", polling))
        );
        this.template.updateFirst(bq, bu, CarrierEvent.class);
    }
}
```

**What you can say**: "Spring provides `MongoTemplate` for database access. We use it to write custom queries instead of relying on auto-generated methods. It abstracts MongoDB operations—queries, updates, insertions—so we don't directly write MongoDB commands. Similar to Mongoose in Node.js or Prisma/TypeORM in TypeScript."

**Confidence Level**: ⭐⭐⭐ Can discuss (don't go too deep)

## 5. Optional Chaining (Null-Safety)

**What it is**: Safely handling values that might be null

**Code Example**:
```java
// Without Optional - manual null checks (verbose)
String eventIdOld = null;
if (paqatoEvent != null) {
    if (paqatoEvent.getEventId() != null) {
        eventIdOld = paqatoEvent.getEventId().toString();
    }
}

// With Optional - clean fluent chain (modern Java)
String eventId = Optional.ofNullable(paqatoEvent)
        .map(PaqatoEvent::getEventId)
        .map(String::valueOf)
        .orElse(null);
```

**What you can say**: "Java's `Optional` is similar to TypeScript's optional chaining (`?.`). It provides a fluent way to handle null values without nested if-statements. Each `.map()` calls the function only if the value exists, and `.orElse()` provides a default. It's one of the cleaner parts of modern Java."

**Confidence Level**: ⭐⭐⭐⭐ Can discuss comfortably

## 6. Function Mapping & Method References

**What it is**: Passing functions as values (functional programming style)

**Code Example**:
```java
protected Map<String, BiFunction<PaqatoShipmentData, PaqatoEvent, String>> 
                        defineExtractors() {
    return Map.of(
        "shipmentType", this::shipmentType,  // Method reference
        "shipmentState", this::shipmentState,
        "eventId", this::eventId
    );
}

// This creates a map where:
// - Key: "shipmentType" (string)
// - Value: a function that takes (PaqatoShipmentData, PaqatoEvent) and returns String
```

**What you can say**: "We use Java's functional programming features—method references (`this::method`) and function mapping. It's similar to storing functions in a dictionary in TypeScript or Python. This allows us to build a map of extractors that apply different logic based on the event field."

**Confidence Level**: ⭐⭐⭐ Can discuss (might skip details)

## 7. Async Processing with @Async

**What it is**: Run code in the background without blocking

**Code Example**:
```java
@Service
public class PaqatoAnnounceService {
    
    @Async("asyncExecutor")  // Run this in background thread pool
    @Retry(name = "PaqatoAnnounceService_ordersCreate")
    public void announceShipment(OrderData order) {
        // This runs asynchronously
        // If it fails, Resilience4j retries it automatically
    }
}
```

**What you can say**: "Spring's `@Async` annotation runs methods in a background thread pool without blocking the caller. Combined with `@Retry`, it automatically retries failed operations. It's like `async/await` in TypeScript, but declarative—you just add the annotation."

**Confidence Level**: ⭐⭐⭐ Can discuss comfortably

## 8. Configuration Properties with Type Safety

**What it is**: Reading configuration from files and accessing it in code

**Code Example**:
```java
// In application.yml:
// paqato:
//   url: https://api.paqato.com/v3/
//   timeout: 5000

@Configuration
@ConfigurationProperties(prefix = "paqato")
public class PaqatoProperties {
    private String url;
    private Integer timeout;
    
    // getters/setters or Lombok @Getter/@Setter
}

// In service:
@Service
public class PaqatoApiService {
    private final PaqatoProperties paqatoProps;
    
    public void callApi() {
        RestTemplate.call(paqatoProps.getUrl()); // Type-safe access
    }
}
```

**What you can say**: "Spring's `@ConfigurationProperties` maps YAML/properties files to Java objects. This is type-safe and eliminates magic strings. Similar to how you'd load `.env` in Node.js but with compile-time safety."

**Confidence Level**: ⭐⭐⭐⭐ Can discuss comfortably

## 10. Lombok for Boilerplate Reduction

**What it is**: Annotations that auto-generate common code

**Code Example**:
```java
// Without Lombok - verbose
public class CarrierEvent {
    private String id;
    private String carrier;
    
    public String getId() { return id; }
    public void setId(String id) { this.id = id; }
    public String getCarrier() { return carrier; }
    public void setCarrier(String carrier) { this.carrier = carrier; }
    // ... and hashCode(), equals(), toString() ...
}

// With Lombok - clean
@Getter
@Setter
@EqualsAndHashCode
@ToString
@Builder
public class CarrierEvent {
    private String id;
    private String carrier;
}
```

**What you can say**: "Lombok uses annotations to auto-generate getters, setters, equals, toString, and builder patterns. It reduces boilerplate significantly—similar to how TypeScript class syntax eliminates Java-style boilerplate, but for Java. The trade-off is adding an annotation processor to the build."

**Confidence Level**: ⭐⭐⭐ Can discuss (brief mention)

## Deep Question Preparation

**Q: "How does Spring's dependency injection work?"**
A: "Spring scans for `@Service`, `@Component`, etc., creates instances, and maintains a registry. When a class declares a dependency in its constructor, Spring looks it up in the registry and injects it. It's similar to a service container pattern."

**Q: "Why use Optional over null checks?"**
A: "Optional forces you to handle the null case explicitly. You can't accidentally skip the check. It makes the intent clear—'this value might not exist.' Plus, chaining `.map()` is cleaner than nested ifs."

**Q: "How do generics improve your code?"**
A: "Without generics, we'd need separate classes for each carrier type (PaqatoStateResolver, DhlStateResolver, etc.). With generics `<T, E>`, we write once and plug in different types. Reusable, DRY, reduces bugs."

**Q: "What's the advantage of externalized configuration?"**
A: "No recompilation to change settings. You can deploy the same jar to dev/staging/prod with different config files. Keeps secrets out of code. Type-safe compared to env vars."

**Q: "How does @Async work?"**
A: "Spring registers a thread pool and routes `@Async` methods to it. The caller gets a Future back immediately and continues. The method runs in the background. It's like wrapping a function in a Promise."
