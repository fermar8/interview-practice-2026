# API Design

## REST Conventions
These are common REST conventions to use as a starting point for your API design, but consider the specific needs of your application and users.

### 1. Use Nouns for Resources
Use nouns to represent the resources in your API:
- Examples: `/users`, `/products`, `/orders`
- Avoid using verbs in resource names
- HTTP methods (GET, POST, PUT, DELETE) already indicate the action

### 2. Use HTTP Methods to Indicate Actions
Use appropriate HTTP methods for the action being performed:
- **GET** – Retrieve a resource
- **POST** – Create a new resource
- **PUT** – Update an existing resource
- **DELETE** – Delete a resource

### 3. Use Plural Nouns for Collections
Use plural nouns to represent collections:
- Example: `/users` for a collection of user resources
- Helps differentiate between a single resource and a collection

### 4. Use Query Parameters for Filtering and Sorting
Allow clients to filter and sort results:
- Example: `/users?age=30` filters users by age
- Example: `/users?sort=name` sorts users by name

### 5. Use Consistent Naming Conventions
Maintain consistency for:
- Resource names
- Query parameters
- Other API elements

### 6. Use Versioning
Allow for API changes without breaking existing clients:
- In URL: `/v1/users`
- In headers: `Accept: application/vnd.myapi.v1+json`

## Validation and Error Handling

### 1. Use Appropriate HTTP Status Codes
- **200** OK – Successful requests
- **201** Created – Successful resource creation
- **400** Bad Request – Invalid requests
- **500** Internal Server Error – Server errors

### 2. Provide Meaningful Error Messages
When an error occurs, provide:
- Specific error details
- The field that caused the error
- Relevant information to help clients troubleshoot

### 3. Validate Input Data
Ensure input data:
- Meets expected format
- Complies with constraints
- Prevents errors and improves quality

### 4. Use Consistent Error Response Formats
Use a consistent format for error responses:
```json
{
  "error": "Error message",
  "details": "Additional information"
}
```

### 5. Log Errors
Log errors on the server side for:
- Debugging and troubleshooting
- Identifying error patterns
- Improving your API over time

## Middleware and Authentication

### 1. Use Middleware for Common Tasks
Use middleware to handle:
- Logging
- Authentication
- Error handling
- Keeps code organized and reduces duplication

### 2. Implement Authentication and Authorization
- **Authentication** – Verify the identity of users
- **Authorization** – Control access to resources
- Protects sensitive data

### 3. Use Secure Authentication Methods
Secure methods include:
- OAuth
- JWT (JSON Web Tokens)
- API keys

Avoid:
- Basic authentication
- Other insecure methods

### 4. Handle CORS
If accessed from web browsers:
- Handle Cross-Origin Resource Sharing (CORS) properly
- Allow requests from different origins while maintaining security

### 5. Rate Limiting
Implement rate limiting to:
- Prevent API abuse
- Ensure API can handle high volume without crashing
- Improve performance and reliability
