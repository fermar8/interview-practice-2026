# Indexes

## Overview
Indexes speed up database read operations but can slow down write operations. It's important to carefully consider which columns to index based on your application's read and write patterns.

## Performance Tradeoff

### Reads (Faster)
- Allow the database to quickly locate data without scanning the entire table

### Writes (Slower)
- Database must update the index every time a record is:
  - Inserted
  - Updated
  - Deleted

## Composite Indexes
Indexes that include **multiple columns**.

### Benefits
- Useful for queries that filter on multiple columns
- Allow the database to use the index to quickly locate relevant records

### Considerations
- Can be larger and slower to update than single-column indexes
- Carefully consider which columns to include based on specific queries

## High-Cardinality Indexes
Indexes on columns with a **large number of unique values**.

### Benefits
- Useful for queries that filter on those columns
- Allow the database to quickly locate relevant records

### Considerations
- Can be larger and slower to update than low-cardinality indexes
- Higher maintenance cost

## Index Strategy
Choose columns to index based on:
- Query patterns in your application
- Read vs. write operation frequency
- Index maintenance cost vs. performance gain
