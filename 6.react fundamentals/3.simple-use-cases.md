# Simple React Use Cases

## Overview

This note explores basic React use cases:

1. Rendering lists and conditional UI
2. Controlled forms
3. Fetching data from an API
4. Lifting state up

## 1. Rendering Lists and Conditional Rendering

### Rendering lists

You can render lists by using `map` on an array and returning JSX for each item.

Important rule:

- Provide a unique `key` so React can track changed, added, or removed items

### Conditional rendering

You can conditionally render UI with:

- Logical operators like `&&`
- Ternary expressions like `condition ? a : b`

### Example

```tsx
import React from 'react';

function ItemList(props: { items: string[] }) {
    return (
        <ul>
            {props.items.map((item, index) => (
                <li key={index}>{item}</li>
            ))}
        </ul>
    );
}

function Greeting(props: { isLoggedIn: boolean }) {
    return (
        <div>
            {props.isLoggedIn ? <h1>Welcome back!</h1> : <h1>Please sign up.</h1>}
        </div>
    );
}
```

## 2. Controlled Forms

Controlled forms are driven by component state.

Form controls (`input`, `textarea`, `select`) use state as their `value`, and update state in `onChange` handlers.

Benefits:

- Full control over form data
- Easier validation and submit handling

### Example

```tsx
import { useState } from 'react';

function NameForm() {
    const [name, setName] = useState('');

    const handleChange = (event: React.ChangeEvent<HTMLInputElement>) => {
        setName(event.target.value);
    };

    const handleSubmit = (event: React.FormEvent<HTMLFormElement>) => {
        alert('A name was submitted: ' + name);
        event.preventDefault();
    };

    return (
        <form onSubmit={handleSubmit}>
            <label>
                Name:
                <input type="text" value={name} onChange={handleChange} />
            </label>
            <button type="submit">Submit</button>
        </form>
    );
}
```

`preventDefault` stops the browser's default form submission behavior (page reload).

## 3. Fetching Data from an API

A common pattern is using `useEffect` to fetch data when the component mounts.

You can use:

- The native `fetch` API
- Libraries like Axios

Best practices:

- Handle loading state
- Handle error state
- Use `async/await` for readability when appropriate

### Example with loading and error handling

```tsx
function DataFetcherWithErrorHandling() {
    const [data, setData] = useState(null);
    const [loading, setLoading] = useState(true);
    const [error, setError] = useState(null);

    useEffect(() => {
        const fetchData = async () => {
            try {
                const response = await fetch('https://api.example.com/data');
                if (!response.ok) {
                    throw new Error('Network response was not ok');
                }
                const data = await response.json();
                setData(data);
            } catch (error) {
                setError(error);
            } finally {
                setLoading(false);
            }
        };

        fetchData();
    }, []);

    if (loading) {
        return <div>Loading...</div>;
    }
    if (error) {
        return <div>Error: {error.message}</div>;
    }

    return (
        <div>
            <h1>Data:</h1>
            <pre>{JSON.stringify(data, null, 2)}</pre>
        </div>
    );
}
```

## 4. Lifting State Up

Lifting state up means moving state to the closest common ancestor of components that need it.

Why it helps:

- Shared state stays centralized
- Multiple child components can read the same source of truth
- Child components can receive both state and updater functions through props

### Example

```tsx
function ParentComponent() {
    const [sharedState, setSharedState] = useState('Initial state');
    return (
        <div>
            <ChildComponent1 sharedState={sharedState} setSharedState={setSharedState} />
            <ChildComponent2 sharedState={sharedState} />
        </div>
    );
}

function ChildComponent1(props: { sharedState: string; setSharedState: React.Dispatch<React.SetStateAction<string>> }) {
    return (
        <div>
            <h2>Child Component 1</h2>
            <p>Shared State: {props.sharedState}</p>
            <button onClick={() => props.setSharedState('Updated state from Child 1')}>Update State</button>
        </div>
    );
}

function ChildComponent2(props: { sharedState: string }) {
    return (
        <div>
            <h2>Child Component 2</h2>
            <p>Shared State: {props.sharedState}</p>
        </div>
    );
}
```

In this setup, the parent owns the state, and both children reflect updates when the state changes.
