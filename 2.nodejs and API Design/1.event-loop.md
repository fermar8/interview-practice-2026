# Node.js Event Loop

## What the Event Loop Is

The event loop is the core mechanism that allows single-threaded JavaScript environments to run non-blocking asynchronous operations.

It keeps scheduling work efficiently while your app runs.

## Main Components

1. Call Stack: Executes synchronous code, one frame at a time.
2. Web APIs / Background Workers: Handle timers, I/O, and other async tasks outside the stack.
3. Task Queues:
   - Macrotasks (for example `setTimeout` callbacks)
   - Microtasks (for example Promise callbacks)
4. Event Loop: Pushes queued callbacks into the call stack when the stack is empty.

## Execution Order Example

```ts
console.log("Start");
setTimeout(() => {
  console.log("Timeout callback");
}, 0);

Promise.resolve().then(() => {
  console.log("Promise callback");
});
console.log("End");
```

Expected output:

1. `Start`
2. `End`
3. `Promise callback`
4. `Timeout callback`

Why this order:

- Synchronous logs run first
- Promise `.then` callback is a microtask
- `setTimeout` callback is a macrotask
- Microtasks run before the next macrotask

## Event Loop Starvation

Heavy CPU-bound synchronous work (for example huge loops or large JSON processing) can block the main thread and freeze event loop progress.

## Scaling Guidance

- For CPU-heavy tasks: use Worker Threads to offload computation.
- For high HTTP traffic: use clustering/process managers (for example PM2/Cluster) to utilize multiple CPU cores.
