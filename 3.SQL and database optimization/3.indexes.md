# Database Indexes

## Why Indexes Matter

Indexes improve read performance by helping the database locate data without full table scans.

Trade-off:

- Faster reads
- Slower writes (insert/update/delete must also update indexes)

## Composite Indexes

Composite indexes include multiple columns.

They are useful for multi-column filtering/sorting patterns, but they can:

- Consume more space
- Cost more to maintain on writes

Choose column order based on real query patterns.

## High-Cardinality Indexes

High-cardinality columns have many unique values.

These indexes are often effective for selective lookups but can still incur write/size costs.

## Practical Guidance

Index intentionally based on workload:

- Prioritize columns used frequently in filters/joins/order clauses
- Reassess indexes when query patterns evolve
- Avoid over-indexing write-heavy tables
