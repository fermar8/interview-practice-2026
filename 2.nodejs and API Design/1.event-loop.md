# Node.js Event Loop

Node.js is a runtime environment for executing JavaScript code outside the browser.
It is built on Chrome's V8 JavaScript engine and uses an event-driven, non-blocking I/O model.

## What the Event Loop Is

The event loop is the core mechanism that allows single-threaded JavaScript environments to run non-blocking asynchronous operations.

It keeps scheduling work efficiently while your app runs.

## Main Components

1. Call Stack: Executes synchronous code, one frame at a time.
2. Web APIs / Background Workers: Handle timers, I/O, and other async tasks outside the stack. For example, `setTimeout`, `setInterval`, and network requests. More in detail, Web APIs are the environment that handles the async work. For example, when you call `setTimeout`, the timer is handled by the Web API, and once it expires, the callback is queued in the task queue to be executed by the event loop.
3. Task Queues:
   - Macrotasks (for example `setTimeout` callbacks). It is different than Web APIs, which are the environment that handles the async work. Task queues are where callbacks from Web APIs are queued to be executed. Callback meaning the function that will be called when the async work is done. For example, the callback passed to `setTimeout` will be queued in the macrotask queue after the timer expires.
   - Microtasks (for example Promise callbacks)
4. Event Loop: Pushes queued callbacks into the call stack when the stack is empty.

## Execution Order Example

```ts
console.log("Start");
setTimeout(() => {
  console.log("Timeout callback");
}, 0);

Promise.resolve().then(() => {
  console.log("Promise callback");
});
console.log("End");
```

Expected output:

1. `Start`
2. `End`
3. `Promise callback`
4. `Timeout callback`

Why this order:

- Synchronous logs run first
- Promise `.then` callback is a microtask
- `setTimeout` callback is a macrotask
- Microtasks run before the next macrotask

## Event Loop Starvation

Heavy CPU-bound synchronous work (for example huge loops or large JSON processing) can block the main thread and freeze event loop progress.

## Scaling Guidance

- For CPU-heavy tasks: use Worker Threads to offload computation.
- For high HTTP traffic: use clustering/process managers (for example PM2/Cluster) to utilize multiple CPU cores.
