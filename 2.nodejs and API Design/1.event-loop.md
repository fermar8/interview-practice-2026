# Event Loop

## Overview
The **Event Loop** is the core mechanism that allows single-threaded environments to perform non-blocking, asynchronous operations. It constantly monitors code execution and schedules tasks efficiently.

## Architectural Components

1. **Call Stack** – Executes synchronous code sequentially (one thing at a time)
2. **Web APIs / Background** – Handles long-running tasks (like network requests or timers) outside the main thread
3. **Task Queues** – Stores callbacks from finished background tasks
   - **Macrotasks** (e.g., `setTimeout`)
   - **Microtasks** (e.g., Promises)
4. **The Loop** – Checks if the Call Stack is empty; if so, pushes the next waiting callback from the queue into the stack

## Event Loop Example

```typescript
console.log("Start");
setTimeout(() => {
  console.log("Timeout callback");
}, 0);

Promise.resolve().then(() => {
  console.log("Promise callback");
});
console.log("End");
```

### Output
```
Start
End
Promise callback
Timeout callback
```

### Explanation
1. "Start" is logged immediately
2. `setTimeout` is called → callback sent to **Macrotask queue**
3. `Promise.resolve()` is called → callback sent to **Microtask queue**
4. "End" is logged immediately
5. Call Stack is empty → Event loop processes **Microtask queue first** → "Promise callback"
6. Then processes **Macrotask queue** → "Timeout callback"

## Event Loop Starvation
This happens when you run heavy CPU-intensive synchronous code (like a massive for loop or large JSON parsing) on the main thread:
- A **synchronous task is blocking**, while an **asynchronous task is non-blocking**
- Completely freezes the event loop
- No other user requests can be processed

### Solutions
- **Heavy CPU calculations**: Use Worker Threads to move that work off the main event loop
- **High volume of HTTP traffic**: Use PM2/Cluster to utilize all CPU cores
